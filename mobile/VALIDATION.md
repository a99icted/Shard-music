# Проверка Android — 15 ноября 2026

## Изменения 0.1.3

Мини-плеер переделан по предоставленному примеру в узкую полосу: одна строка
названия/исполнителя, воспроизведение/пауза слева, сердце и закрытие справа,
индикатор прогресса снизу. Закрытие останавливает воспроизведение и очищает
очередь, сохраняя файлы библиотеки. Развёрнутая панель содержит небольшой
значок обложки справа от заголовка (обложки отдельных треков в модели пока нет),
перемотку с временем, повтор/предыдущий/паузу/следующий/меню и широкую кнопку
«Добавить в избранное». В меню — перемешивание и очередь, режимы подписаны.

Уведомление заменено собственным RemoteViews-макетом с шестью кнопками в
развёрнутом виде: перемешивание, предыдущий, пауза, следующий, повтор, сердце.
Media3 продолжает управлять жизненным циклом foreground-сервиса и проверять
команды. Прежнее ограничение предыдущего трека для системных контроллеров
снято. Для пользовательского уведомления запрашивается POST_NOTIFICATIONS на
Android 13+, при отказе воспроизведение продолжает работать.

`PlaybackControlsTest` нажимает кнопки настоящего RemoteViews через их
PendingIntent, проверяя воспроизведение/паузу, предыдущий/следующий, избранное,
перемешивание и повтор. Дополнительно проверены пауза и возобновление через
мини-плеер, перемотка через ползунок большой панели, кнопка избранного,
изменение режима через меню, закрытие без удаления трека и синхронизация
подписей с платформенной MediaSession. Система проверялась на Android 15,
эмулятор x86_64, 360 dp. Оболочка физического ARM64-телефона не проверялась.

При повторной проверке обнаружено зависание одновременных локальных JNI-вызовов:
JVM-стек показал три worker-потока в NativeBridge.dispatch, нативный стек —
ожидание pthread mutex в библиотеке при локальных операциях с базой.
Локальные команды Android Core теперь выполняются
последовательно через coroutine Mutex; metadata/sync и отмена остаются независимыми,
чтобы передача не блокировала подтверждение дубликатов. Убран двойной запрос
библиотеки при старте. В тест добавлены четыре клиента с десятью чтениями и
изменениями избранного каждый; изменения относятся только к собственному треку.

Новые таймеры не работают с выключенным экраном: позиция в Compose обновляется
раз в секунду только при видимом плеере и воспроизведении, позиция уведомления —
раз в пять секунд только при воспроизведении и включённом экране. Для времени
уведомления используется системный Chronometer. Индикатор уведомления открывает
плеер для перемотки, поскольку RemoteViews не поддерживает интерактивный SeekBar.
Android добавляет системный заголовок/рамку к собственному макету; внешний вид
на разных оболочках может отличаться.

Итог 0.1.3: **7 unit-тестов и 4 instrumentation-теста прошли**, сетевой тест
YouTube пропущен (загрузчик в этой задаче не менялся). Lint: **0 ошибок,
10 предупреждений** о новых версиях зависимостей. Оптимизированные release APK
arm64-v8a и x86_64 собраны и подписаны development-ключом для обновления прежних
локальных сборок, подписи проверены apksigner. Все шесть ELF-библиотек внутри
ARM64 APK проверены: ELF64, `e_machine=183` (AArch64). x86_64 release установлен
поверх debug-сборки, холодный запуск успешен. Физический телефон не виден в ADB,
установка на него не выполнялась. Собственные тестовые треки очищены.

## Изменения 0.1.2

На эмуляторе Android 15 (360 dp) проверена системная медиапанель: одновременно
видны сердце, воспроизведение/пауза, следующий, перемешивание и повтор.
При нажатии обновляются состояние избранного и значки режимов. Предыдущий трек
сохранён в большом плеере, а системный слот отдан сердцу, чтобы поместились все
три запрошенных действия.

В приложении проверены отдельное сердце мини-плеера и подписанные режимы
большого плеера; внутренний ползунок громкости и вкладка «Плеер» в настройках
удалены. Громкость ExoPlayer остаётся 1.0 даже при сохранённом старом значении
0.23 в настройках — теперь действует только системная регулировка.

`PlaybackControlsTest` проверяет настоящее уведомление с токеном платформенной
MediaSession: мини-плеер добавляет трек в избранное, системная команда убирает
его, приложение отражает изменение, а команды shuffle/repeat меняют и плеер,
и сохранённые настройки. В обратную сторону смена повтора в интерфейсе
обновляет подпись системной команды. Проверяется цикл off → all → one → off.
Начальные режимы тест задаёт и через контроллер, чтобы результат не зависел от
ранее работающей медиасессии. Тест удаляет только собственный WAV и трек.

Состояния обновляются по событиям, без фонового опроса. Записи режимов идут
последовательно, переключение избранного защищено mutex. Оформление уведомления
Android 8–12 задано через Media3; визуальная проверка в этой среде выполнена
только на Android 15, оболочка физического телефона отдельно не проверялась.

По отчёту о таймауте EJS/QuickJS и `SSL: UNEXPECTED_EOF_WHILE_READING` перед
HTTP 403 добавлен один повтор извлечения через секунду. Это отдельный путь от
обновления yt-dlp: работает и при неизменившейся версии, обычный 403 его не
запускает. Unit-тесты воспроизводят сочетание таймаута и 403, успешный повтор,
постоянный сетевой сбой (ровно две попытки), отмену и обычный 403 (без повтора).
В интерфейсе для сетевого обрыва показывается отдельное объяснение.

Итоговые проверки 0.1.2: **7 unit-тестов и 5 instrumentation-тестов прошли**,
без пропусков. Сетевой тест включён явно: официальный загрузчик обновлён,
тестовая запись `gHKT4uU8Zng` скачана за один запуск теста (20 секунд).
Песни из пользовательского отчёта в этой среде не проверялись.
Android Lint: **0 ошибок, 10 предупреждений** о более новых версиях зависимостей.
Оптимизированные release APK для arm64-v8a и x86_64 собраны с R8 и сжатием
ресурсов, подписаны тем же development-ключом для обновления прежних локальных
сборок; подписи проверены apksigner. x86_64 APK установлен поверх debug-сборки,
холодный запуск главной успешен. Физический телефон в ADB на момент проверки
отсутствовал; установка на него не выполнялась.

## Проверка 0.1.1

Среда: Android 15 / API 35, x86_64, эмулятор Pixel 6 с размером экрана
720 × 1280 и плотностью 320 dpi (360 dp по ширине).

Проверено на реальном Android runtime:

- Главная открывается на плейлистах; доступны избранное и все треки.
- Настройки открываются отдельно; оформление, загрузки и статистика показывают
  только содержимое своей вкладки. Возврат в библиотеку работает.
- Общий Rust/JNI импортирует WAV, создаёт плейлист, добавляет трек в избранное,
  меняет метаданные и удаляет только данные, созданные тестом.
- Android MediaSession декодирует импортированный файл, начинает воспроизведение,
  принимает перемотку и паузу. Тест запускает Activity перед запросом аудиофокуса,
  как требует Android 15 для первоначального воспроизведения.
- Загрузчик обновляется через официальный stable endpoint до **2026.10.26**.
- Сетевой instrumentation-тест скачал аудио пятисекундной публичной записи
  `gHKT4uU8Zng` из актуальных тестов yt-dlp; файл проверен и удалён тестом.
- Через обычный интерфейс вставлена та же ссылка и нажата кнопка скачивания:
  WorkManager скачал M4A, Rust добавил его в библиотеку; итоговый отчёт
  «Добавлено: 1 из 1. Ошибок: 0.».

Unit-тесты: 4 проверки, включая сочетание старого предупреждения/SABR/HTTP 403
и ограничение длинного русского отчёта по размеру UTF-8 для WorkManager.
Полный запуск AndroidJUnitRunner с включённым сетевым тестом: **OK (4 tests)**.
Android Lint: 0 ошибок; предупреждения касаются доступных новых версий зависимостей.

Это проверка на эмуляторе, а не измерение энергопотребления физического телефона.
Обновления загрузчика не выполняются при запуске или локальном прослушивании.
Проверки и повторные попытки ограничены; кеш подписей переиспользуется.
Доступность конкретных записей, ограничения аккаунта/региона и работа конкретной
сети YouTube остаются внешними условиями.
