# Shard для Android

Android-клиент находится в `mobile/`, десктопный клиент — в корне репозитория.
Общая прикладная логика написана на Rust и подключается из того же `shard`,
что использует Windows-приложение. Это не отдельная переписанная база или новый
протокол синхронизации.

Интерфейс — Kotlin / Jetpack Compose, воспроизведение — Android Media3.
GPUI не поддерживает Android. Системная оболочка нужна для аудиофокуса,
Bluetooth, экрана блокировки, уведомлений, scoped storage и ограничений фоновой
работы Android. WebView, Electron и постоянного браузерного процесса нет.

Минимальная ОС: **Android 8.0 / API 26**. Target / compile SDK: **35**.
Сборки: **arm64-v8a** для современных телефонов и **x86_64** для эмуляторов.
32-битные ARM-устройства в текущую конфигурацию не входят.

## Навигация 0.1.3

Приложение открывается в «Моя музыка»: вкладки «Плейлисты», «Избранное» и
«Все треки». На главной — карточки коллекций и сетка плейлистов, создание
плейлиста и добавление музыки. В списке треков доступны поиск, воспроизведение,
перемешивание и меню трека. Мини-плеер открывает полное управление и очередь.

Настройки разделены на вкладки: **Оформление / Загрузки /
Синхронизация / Статистика / О приложении**. Статистика находится только
в настройках. Статус загрузки в медиатеке ведёт прямо на вкладку «Загрузки».
Добавление музыки открывает панель с отдельными кнопками для файлов и ссылки.

Мини-плеер — узкая полоса: воспроизведение/пауза, название и исполнитель в одну
строку, сердце, закрытие и тонкий индикатор прогресса снизу. Нажатие на название
открывает компактную панель: заголовок, исполнитель, небольшой значок обложки,
перемотка с временем, повтор, предыдущий, пауза, следующий и меню.
В меню — перемешивание и очередь. Текущие режимы подписаны под кнопками.
Широкая кнопка «Добавить в избранное» меняется на «В избранном».
Закрытие мини-плеера останавливает музыку и очищает очередь, файлы сохраняются.
Дополнительной громкости приложения нет:
действует системная громкость Android, без сохранённого уменьшения сигнала.

Шторка использует собственный RemoteViews-макет уведомления: перемешивание,
предыдущий, воспроизведение/пауза, следующий, повтор и сердце — все шесть кнопок
в развёрнутой карточке. Стандартный MediaStyle ограничивает число кнопок пятью,
поэтому для этого макета применяется DecoratedCustomViewStyle. Компактная
карточка содержит название, исполнителя, паузу и сердце. Android добавляет
системный заголовок и кнопку раскрытия; оформление зависит от оболочки.
MediaSession, гарнитура и аудиофокус сохраняются; прежнее ограничение команды
«предыдущий» для системных контроллеров снято. На Android 13+ при первом запуске
музыки запрашивается разрешение уведомлений — для собственной карточки оно нужно.
Индикатор прогресса уведомления обновляется раз в пять секунд только при
воспроизведении и включённом экране. Счётчик времени ведёт системный Chronometer.
При выключении экрана таймер прекращается. Индикатор открывает перемотку в
плеере: RemoteViews не поддерживает интерактивный ползунок SeekBar.
Повтор переключается по кругу: выключен → вся очередь → один трек.

## Обновление загрузчика YouTube

Перед скачиванием проверяется официальный стабильный выпуск yt-dlp, не чаще
раза в сутки. После неудачной проверки действует часовой интервал. В настройках
«Загрузки» есть принудительное обновление и версия установленного загрузчика.
Ни запуск приложения, ни обычное локальное прослушивание эту проверку не вызывают.

Современный YouTube требует решатель JavaScript-подписей: используется QuickJS
из Android-библиотеки и официальный EJS-компонент yt-dlp. Подписи и компоненты
кешируются в очищаемом Android-кеше. При 403 / ошибке подписи выполняется одна
попытка обновления; повтор скачивания выполняется только если версия изменилась.
Отдельно при таймауте или обрыве TLS/соединения выполняется один повтор через
секунду с той же версией, в том числе если после сбоя EJS в логе появился 403.
Обычный 403 без признаков сетевого обрыва этого повтора не вызывает.
Обновление и запуск загрузчика защищены одним mutex, чтобы не заменить файл
под работающим процессом.

Предупреждение «older than 90 days» само по себе не означает ошибку загрузки.
Прежняя встроенная версия 2025.11.12 могла получать HTTP 403 после изменений
YouTube/SABR. Интерфейс показывает краткую причину сбоя, а исходный отчёт —
по кнопке «Технические подробности», с возможностью копирования. Обновление
не снимает ограничения доступа к закрытым, возрастным или недоступным записям.

## Функции

| Возможность десктопа | Реализация Android |
| --- | --- |
| Локальный импорт | Системный выбор нескольких файлов и Android «Поделиться»; импорт и метаданные через общий Rust TrackService |
| Библиотека и поиск | По названию / исполнителю, ленивый список Compose |
| Плейлисты | Создание, переименование, добавление / удаление трека, удаление плейлиста без удаления музыки |
| Избранное | Общий FavoritesService; сердце в списке, мини-плеере, большом плеере и шторке |
| Очередь | Media3 timeline, добавление, выбор, удаление, следующий / предыдущий трек |
| Прослушивание | Пауза, перемотка, shuffle, repeat off / all / one; громкость регулирует Android |
| Фоновое воспроизведение | MediaSessionService, уведомление, экран блокировки, Bluetooth / гарнитура, аудиофокус |
| Темы и язык | Forest / Onyx / Pick Me / Cosmic, русский / английский |
| Оформление плейлистов | Обложка, цвет шапки HEX, фон и размытие; общие Rust-сервисы |
| Общий фон | Сохранение картинки и размытия через BackgroundService |
| Статистика | Тот же StatisticsService; измеряется время реального воспроизведения, а не позиция перемотки |
| YouTube | Трек / публичный плейлист через Android-сборку yt-dlp и FFmpeg |
| Spotify / Яндекс Музыка | Общий Rust-парсер публичных метаданных и тот же алгоритм поиска подходящей записи YouTube |
| Прогресс / ошибки загрузок | WorkManager, отмена, частичные результаты и отчёт в настройках |
| LAN-синхронизация | Тот же SyncService / протокол v2: код подключения, трек / плейлист / вся библиотека, прогресс, возобновление |
| Дубликаты | Пропуск / копия для каждого совпадения или всех, общие настройки предупреждений |
| Трей и панель задач Windows | Android-уведомление и системная медиасессия |

Обложки, фоны, удаления и настройки не передаются через LAN: это ограничение
существующего десктопного протокола, а не отдельный формат Android. QR-сканер
в эту версию не включён: подключение выполняется копированием кода.

Поддержка декодирования отдельных кодеков определяется Android Media3 и
устройством. Основные MP3, FLAC, WAV, AAC/M4A, Ogg/Vorbis и Opus поддерживаются;
AIFF преобразуется в FLAC без потерь при первом добавлении в очередь, результат
кешируется, исходный файл сохраняется. Экзотические варианты PCM требуют
отдельной проверки. Загрузки сохраняют
подходящий исходный кодек вместо обязательной конвертации в MP3.

## Энергопотребление

- Декодирование и медиасессию обслуживает Android. Audio offload запрашивается
  при поддержке устройства; при отсутствии поддержки остаётся обычный декодер.
- Локальное прослушивание не запускает сетевой сервер, yt-dlp или FFmpeg.
- LAN включается явно; при уходе в фон выключается после активной передачи.
  Неактивная открытая сессия также ограничена десятью минутами. Автозапуска при
  загрузке телефона и периодического поиска устройств нет.
- Блокировка сна для LAN удерживается только во время передачи, с таймаутом.
  Для музыки блокировку обслуживает Media3. Сервисы не запрашивают исключение
  из системной оптимизации батареи.
- WorkManager выполняет загрузки последовательно, ждёт сеть и достаточный
  заряд батареи. По умолчанию включена неметерируемая сеть; можно потребовать
  подключение зарядки. Параллельные фрагменты отключены, число повторов ограничено.
- yt-dlp / Python / FFmpeg инициализируются при первой загрузке. MP3-транскодирование
  по умолчанию не выполняется.
- Обновление позиции раз в секунду действует только в видимом мини-плеере или
  открытом большом плеере, при воспроизведении и видимой Activity. На паузе и в
  фоне опрос интерфейса останавливается. Состояния кнопок обновляются по событиям.
- Обновление полосы прогресса шторки раз в пять секунд работает только во время
  воспроизведения с включённым экраном; выключение экрана отменяет таймер.
- Статистика записывается пакетами раз в минуту и при паузе / смене трека /
  завершении сервиса. При принудительном уничтожении процесса возможна потеря
  неполной последней минуты статистики.
- Картинки и размытие рассчитываются при изменении оформления. При проигрывании
  не выполняется постоянное размытие каждого кадра. Перед обработкой Rust
  Android уменьшает крупные фотографии через sampled decode до 2048 пикселей
  по длинной стороне, чтобы не декодировать исходные 40 MP в памяти.
- Rust release: LTO, один codegen unit, оптимизация размера, удаление символов.
  Desktop-зависимости, включая GPUI и генерацию Windows-иконок, не входят в mobile.
- APK разделены по ABI, Rust-библиотека выровнена на 16 KiB для новых устройств.

Это архитектурные меры; сравнение расхода батареи на физических устройствах
требует измерений. Процент экономии без такого измерения не заявляется.

## Сборка

Нужны Rust stable, JDK 17 или 21, Android SDK platform 35, build-tools 35.0.0,
NDK **27.2.12479018**. Укажите `JAVA_HOME` и `ANDROID_HOME`.

Windows, из корня репозитория:

```powershell
$env:JAVA_HOME = 'C:/Program Files/Java/jdk-21.0.10'
$env:ANDROID_HOME = "$env:LOCALAPPDATA/Android/Sdk"
./mobile/build-android.ps1
```

Linux / macOS:

```sh
sh mobile/build-android.sh
```

Скрипт устанавливает Rust targets и cargo-ndk 4.1.2, затем Gradle сам собирает
Rust-библиотеку для обоих ABI и упаковывает её в APK. Gradle Wrapper проверяет
SHA-256 дистрибутива. JNI-символы сохраняются при R8.

Результат: `mobile/android/app/build/outputs/apk/debug/app-arm64-v8a-debug.apk`
и `app-x86_64-debug.apk`. Это debug-сборки для проверки, не подписанные магазинным
ключом релизы. Ключи подписи и локальные пути SDK исключены из Git.

`./mobile/build-android.ps1 -Release` / `sh mobile/build-android.sh assembleRelease`
включает R8 и удаление неиспользуемых ресурсов. Release-ключ задаётся отдельно
в конфигурации распространения и никогда не хранится в репозитории.

Workflow `.github/workflows/android.yml` собирает и проверяет Android и сохраняет
APK в артефактах GitHub Actions. Он не публикует приложение в Google Play и не
создаёт GitHub Release.

## Проверка

```powershell
cargo test --locked --no-default-features -- --test-threads=1
cd mobile/android
./gradlew.bat assembleDebug testDebugUnitTest lintDebug
./gradlew.bat connectedDebugAndroidTest
```

Последняя команда требует Android-устройство с разрешённой USB-отладкой или
эмулятор. Android-тест использует реальный JNI, SQLite и импорт WAV, затем
проверяет плейлист, избранное, метаданные и удаление созданных им данных.
Он не удаляет существующую библиотеку.

Compose-тест проверяет стартовую медиатеку, вкладки коллекций и отдельные
вкладки настроек. Unit-тесты проверяют обработку настоящего сочетания
предупреждений/403 и ограничение отчёта по байтам UTF-8 для WorkManager.
Сетевой тест выключен по умолчанию. Для явной проверки обновления и скачивания
короткой публичной записи из тестов yt-dlp:

```powershell
./gradlew.bat connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.class=music.shard.mobile.DownloaderNetworkTest' '-Pandroid.testInstrumentationRunnerArguments.downloaderNetwork=true'
```

Ручная проверка перед распространением:

1. Импортировать несколько MP3/FLAC/M4A/Opus; проверить поиск и повторный запуск.
2. Запустить музыку, погасить экран, проверить кнопки гарнитуры, паузу при
   потере аудиофокуса и отключении наушников.
3. Проверить очередь, shuffle, все режимы repeat, перемотку и статистику.
4. Передать музыку ПК → Android и обратно; проверить дубликаты, отмену,
   повторную передачу после обрыва и работу с погашенным экраном.
5. Скачать разрешённый трек и открытый плейлист, проверить отмену, отчёт об
   ошибках и ожидание Wi-Fi / зарядки.
6. Сравнить `adb shell dumpsys batterystats music.shard.mobile` для локального
   проигрывания и простоя; учитывать громкость, Bluetooth и режим экрана.

Данные Android находятся в приватном `files/shard` и используют ту же схему
SQLite v6. Для переноса музыки с ПК используйте встроенную LAN-синхронизацию.
Удаление Android-приложения удаляет его приватную библиотеку.

## Структура

- `native/` — небольшой Rust cdylib / JNI-мост, без небезопасных указателей.
- `../src/mobile.rs` — типизированная граница команд к общим Rust-сервисам.
- `android/` — Android Gradle-проект, Compose, Media3, WorkManager и адаптер yt-dlp.
- `android/app/src/androidTest/` — проверка библиотеки через реальный JNI.
- `android/app/src/test/` — проверка порядка плейлистов / избранного.

Сторонние компоненты перечислены в `THIRD_PARTY_NOTICES.md`.
