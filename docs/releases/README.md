## Состав коммита

Включите исходники Windows и Android, `mobile/native`, Gradle wrapper,
конфигурацию Android CI, общие Rust-модели и JNI, тесты, ресурсы, документацию,
манифесты и lock-файлы. Сохраните изменения `vendor/gpui`: они нужны для SVG
и освобождения изображений в Windows.

Не включайте `dist`, личную библиотеку, ключи подписи, скачанные инструменты,
`target`, Android `.gradle`, `app/build` и сгенерированные `jniLibs`.
JNI-библиотеки собираются Gradle-задачей `buildRust` из исходников.

**В текущей истории Git уже отслеживаются `.gradle`, `app/build` и два JNI-бинарника.**
Новый `.gitignore` не прекращает отслеживание ранее добавленных файлов.
При подготовке индекса уберите их из отслеживания, сохранив файлы на диске:

```powershell
git rm -r --cached -- mobile/android/.gradle mobile/android/app/build mobile/android/app/src/main/jniLibs
```

Команда изменяет только индекс; для этой подготовки README она автоматически
не выполнялась. Не отменяйте другие изменения рабочего дерева.
Перед коммитом проверьте `git diff --cached --stat` и `git diff --cached --check`:
вместо обновления кешей должны быть их удаления из Git и добавление исходников.
Удаление этих ранее отслеживаемых каталогов создаст большой diff; это очистка
репозитория, а не удаление Android-приложения.

После подготовки и проверки индекса сообщение можно передать из файла:

```powershell
git commit -F docs/releases/0.1.6-commit.txt
```

## Вложения релиза

Файлы берутся из `dist`; в исходный Git-коммит их добавлять не нужно:

- `Shard-0.1.6-Setup-x64.exe` и `.exe.sha256`.
- `Shard-Android-0.1.8-arm64-v8a.apk` и `.apk.sha256`.
- `Shard-Android-0.1.8-x86_64.apk` и `.apk.sha256`.
- `Shard-0.1.6-manifest.json`.
- `Shard-0.1.6-verification.json`.
- `Shard-Android-0.1.8-verification.json`.

Windows 0.1.6 и Android 0.1.8 используют ручной LAN-протокол v2.
Не называйте этот выпуск реализацией live-синхронизации: она остаётся проектом.
Описание содержит текущую development-подпись APK и ограничения проверки.
