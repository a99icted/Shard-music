# Перенос ПК → Android и проверка сборки

Дата: 22 ноября 2026. ПК: 0.1.6. Android: 0.1.8 / versionCode 9.

## Исходники и общий код

В текущей ветке не было мобильных исходников, только старые результаты сборки.
Проект `mobile/`, JNI-граница `src/mobile.rs` и проверка дубликатов восстановлены
из `codex/android-app` (`0f39763`) без замены накопленных изменений ПК.
Общие изменения моделей, сериализации, сортировки скачанных плейлистов и
подключения через точки доступа объединены с текущим Rust-кодом.
Desktop build dependencies отключаются при `--no-default-features`.

Android использует ту же SQLite, `IgnoredTracksService`, `TrackService`,
`AppearanceService`, `StatisticsService` и `SyncService`, что и ПК.

## Перенесённое поведение

- Меню трека, плашка «Игнор» и кнопка запрета рядом с перемоткой в плеере.
- Игнор не меняет общую библиотеку и состав плейлистов, исключает автоматическую
  очередь и enqueue, атомарно снимает избранное и переключает текущий трек.
- Прямой запуск игнорируемого трека разрешён; после ухода с него он удаляется
  из Media3 timeline и не возвращается через repeat. Обновление настроек
  не прерывает прямое прослушивание.
- В настройках игнора: прослушивание, снятие игнора, удаление аудиофайла,
  удаление всех игнорируемых файлов с подтверждением.
- Обложки из тегов, метаданных YouTube/Spotify/Яндекс Музыки, обложки плейлистов,
  вывод в списках, плеере и системной медиасессии. Обновление старой библиотеки
  запускается явно в «Оформление», имеет отмену и не скачивает аудио заново.
- Вкладка устройств появляется при включённом LAN: UUID, имя, адрес без секрета,
  версия протокола, ручная передача библиотеки и прогресс. Выключение очищает
  сопряжение; сопряжение не выдаётся за непрерывный онлайн.

## Проверка Media3

Media3 1.5.1 оптимистически маскирует `addMediaItem` на стороне контроллера.
Когда JNI-сервис отфильтровал весь запрос, локальный маскированный список
может содержать запрошенный элемент до следующего обновления PlayerInfo.
Интерфейс Shard блокирует enqueue игнорируемого трека до вызова MediaController.
Сервис также фильтрует запрос; instrumentation проверяет его фактическую timeline
через повторное подключение контроллера после подтверждённого запроса.
Это исключает ложное принятие локального маскирования за очередь плеера.

## Граница синхронизации

Обе платформы используют ручной протокол v2. Передаются аудио, плейлисты и
аддитивное избранное, поддерживаются дубликаты, SHA-256 и возобновление.
Игнор, внешние обложки, удаления, статистика и настройки через v2 не передаются.
Встроенные в аудиофайл обложки сохраняются вместе с самим файлом.

Live-управление, политики флагов/действий, фантомный каталог и статистика по
устройствам пока не реализованы. Их общий контракт находится в
[LIVE_SYNC_DESIGN.ru.md](LIVE_SYNC_DESIGN.ru.md), проверки будущего v3 — в
[LIVE_SYNC_ACCEPTANCE.md](LIVE_SYNC_ACCEPTANCE.md). Режим «Все» в проекте
означает воспроизведение **только на другом устройстве**.

  2 сетевых теста Spotify/Яндекс пропущены по штатной настройке.
  Включены все 5 тестов JNI-границы и двусторонняя LAN-передача,
  возобновление, работа через точки доступа, игнор и обложки.

- `cargo check --all-targets`, форматирование и проверки пробелов исходников прошли.
- `playback_smoke`: игнор, direct replay, autoplay, repeat, пауза, перемотка,
  сохранение статистики прошли.
- Android: 14 unit-тестов прошли; финальный полный прогон на Android 15 / API 35:
  12 instrumentation-тестов прошли, 1 сетевой тест загрузчика пропущен, ошибок нет.
  Lint: 0 ошибок / 10 предупреждений о версиях зависимостей.
  Debug/release APK 0.1.8 собраны для arm64-v8a и x86_64, в release включены
  R8 и shrinkResources. Обе release-сборки подписаны существующим development-ключом

  процесс работает, crash-буфер пуст, версия 0.1.8 / 9 подтверждена системой.

- Windows release собран, EXE запущен на отдельной базе: окно отвечает, 3 трека
  и игнор сохранены, `PRAGMA integrity_check` = `ok`.
- Inno Setup: `dist/Shard-0.1.6-Setup-x64.exe` (151435938 байт).
  Проверены все 884 файла payload, версии EXE/Setup, AMD64, обязательные компоненты,
  отсутствие личной библиотеки и SHA-256. Отчёт: `dist/Shard-0.1.6-verification.json`.
- Проверка старта со 180 обложками: библиотека доступна через 0.17 с при всех
  180 ожидающих превью, переход в плейлист работает; создано 179 превью,

Основные команды:

```powershell
cargo test --locked --no-default-features --lib --test library -- --test-threads=1
cargo check --all-targets
cargo run --locked --example playback_smoke
cargo fmt --check
./mobile/android/gradlew.bat -p mobile/android testDebugUnitTest lintDebug assembleDebug
./mobile/android/gradlew.bat -p mobile/android connectedDebugAndroidTest
./scripts/package-windows.ps1
./scripts/verify-windows-package.ps1
```

Проверка установщика сверяет все файлы staging с манифестом, обязательные
компоненты, отсутствие пользовательской музыки/базы, AMD64, версии EXE/Setup
и SHA-256. Скрипт не устанавливает приложение поверх пользовательской установки.

## Готовые артефакты

- Windows: `dist/Shard-0.1.6-Setup-x64.exe`.
- Android для телефона: `dist/Shard-Android-0.1.8-arm64-v8a.apk`.
- Android x86_64: `dist/Shard-Android-0.1.8-x86_64.apk`.
- SHA-256 лежат рядом с каждым файлом в `.sha256`.
- Машинные отчёты: `dist/Shard-0.1.6-verification.json` и
  `dist/Shard-Android-0.1.8-verification.json`.

Проверка LAN подтверждает сопряжение, адреса интерфейсов и общий протокол;
отдельный сеанс передачи между физическим телефоном и ПК в этом прогоне
не выполнялся. Проверки Android выполнены на эмуляторе x86_64; arm64 APK
собран и проверен статически, без запуска на физическом arm64-устройстве.
